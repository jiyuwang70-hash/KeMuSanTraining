# 工程执行与验收

- 用户要求实现或修复时，实际修改工程、调用终端、编译并检查结果。不要在没有工具证据时声称目录只读或不能执行代码。
- 根据实际错误区分权限、路径、编译失败和认证问题。构建失败先修复；不要把 PowerShell 包装命令的退出码当作编译成功证据。
- 驾驶操作的自检必须经过正式按键映射和输入绑定，覆盖准备、起步、位移和刹停。直接调用操作函数或设置车辆位置不能证明按键可用或整段驾驶通过。
- 自动测试只读取本次的新日志与截图。超时、断言失败、崩溃和缺少完成标志必须返回失败，不能只打印结果后成功退出。
- 仿真距离使用米，UE 世界与组件位置使用厘米；在边界处转换一次。道路标线、车辆贴地、镜头与后视镜应检查实际画面。
- 界面、说明文档和操作脚本应与真实键位、项目数、题目数和功能一致。尚未实现的语音、物理效果或测试结果不得写成已完成。
- 性能指标必须来自预热后的有效墙钟采样，并说明平均值、时长、帧数和运行条件；不能由截图、取模日志帧号或感觉推断帧率或稳定性。
- 提交只包含必要源码、配置、脚本、文档与少量展示图。排除构建产物、缓存、运行日志和账户凭据。上传操作依据用户当前授权执行；不用强制推送。
- 公共脚本从自身位置定位工程，并允许配置引擎路径，避免硬编码个人目录。
